🐭 Micromouse Motion Lab

A palm-sized robot solves a maze, then races the solution in a few seconds. Finding the path is the easy part. The hard part is how fast you are allowed to go around every corner, and how to shape the corners so you can go faster.

🧩 16×16 cells
📏 18 cm per cell
🎯 goal in the centre
🔎 search run, then ⚡ speed run
The pipeline

From maze to motion in four steps

1 🔎

Search online

Explore with flood fill: every cell stores its distance to the goal, updated as new walls are seen.

2 🗺️

Plan the path offline

Pick the route that is fastest to drive, which is not always the one with the fewest cells.

3 🧱

Compile moves offline

Turn the cell list F F R F L… into a chain of pre-tuned moves from a turn library.

4 📈

Speed profile offline

Accelerate on straights, brake just in time, hold the turn speed that grip allows.

Where this sits in our motion planning course

Lecture 1 defines trajectory = path + velocity profile. A micromouse speed run is built exactly that way, so almost every idea from the first three lectures shows up in a 25 cm robot.

Lecture 2

🧩 Grid cell decomposition

"Uniform grid: resolution complete, curse of dimensionality"

The maze is a ready-made uniform grid: 256 nodes, walls are missing edges. A rare case where the grid is the real world, so resolution costs nothing.

Lecture 2

📐 C-space obstacles

"COB = configurations where the robot intersects WOB"

Shrink the mouse to a point and grow the walls by half its width. That decides whether a diagonal fits between posts. On a diagonal the body is rotated, so the real C-space is (x, y, θ).

Lectures 2 + 3

🌊 Bellman and Dijkstra from G

"Open node G, uG = 0 ... uj = min(uk + akj)"

Micromouse flood fill starts at the goal and spreads outward, giving the cost from every cell. With all edges = 1 it is breadth-first search. Put time on the edges and it becomes true Dijkstra, and A* can speed it up.

Lecture 1

⏱️ Time, not distance

"Optimal trajectory planning (time, energy, not distance)"

The fewest cells is not the fastest run. Long straights and diagonals beat a short, twisty route. The race below drives the same cells three ways.

Lectures 1 + 3

🛣️ Path-velocity decomposition

"Optimize motion along a specified path"

Fix the path first (turn library), then find the fastest speed along it in the phase plane (s, ṡ) with a forward and a backward pass.

Lecture 1

🔁 Online vs offline

"Online: task changes during motion, react, sensor based"

The search run is online: new walls appear and the map re-floods. The speed run is offline: the task is known, compute everything, then move.

Honest limit

⚠️ Near-optimal, not optimal

Path and speed are never optimised together. The turn shapes are hand-tuned and chosen before the speed plan. That is the price of path-velocity decomposition: fast to compute, but the true time-optimal trajectory could bend the path differently.

Interactive 1 · the search · 📚 Dijkstra from the goal

Flood fill: every cell learns its distance to the cheese 🧀

Exactly like the Dijkstra slides: open the goal with cost 0, then every neighbour gets uj = min(uk + akj). Once the wave reaches the start, the mouse just rolls downhill: always step to the neighbour with a smaller number. That is Bellman's principle in action.

👆 Tap any wall or gap to add or remove a wall. That is the mouse discovering a wall during the search run. The whole map re-floods at once, because Dijkstra already gave the cost from all nodes.

Here every move costs 1, so this is breadth-first search. Competitive mice put estimated time on each edge (a turn costs more than a straight), which makes it full Dijkstra and can pick a longer but faster route.

The math behind it

Three ideas carry the whole talk

1 · Corner speed

v_max = √(a_lat · r)

Lateral acceleration is v²/r. Double the radius and you get about 41% more speed through the turn.

2 · Friction circle

√(a_x² + a_y²) ≤ μ·(g + F_fan/m)

Grip is shared: braking while turning leaves less for the turn. A fan adds downforce, which raises the whole circle.

3 · Time-optimal profile

forward pass + backward pass

Along a fixed path, max acceleration forward, max braking backward, take the lower curve. That is the speed plan.

// the speed planner used by every mouse on this page
vlim[i] = min(v_top, sqrt(a_max / |curvature[i]|))      // corner limits
v[0] = 0
for i in 0..n-1:   v[i+1] = min(vlim[i+1], sqrt(v[i]² + 2·a_free(v[i])·ds))   // accelerate
for i in n-1..0:   v[i]   = min(v[i],      sqrt(v[i+1]² + 2·a_free(v[i+1])·ds)) // brake in time
// a_free(v) = sqrt(a_max² − (v²·curvature)²)   ← what's left of the friction circle

Link to our course: this is the path-velocity decomposition from Lectures 1 and 3, and time-optimal motion along a specified path, the same problem solved for robot arms by Bobrow, Dubowsky & Gibson and by Shin & McKay (1985). A micromouse is the clean 2D version: the path is fixed by the maze, and only the speed along it is free.

Simplified model: point mass, one grip number, perfect tracking. Real mice also fight motor torque curves, wheel slip, sensor noise and wall corrections, which is why top teams tune each library turn by hand on a real maze.
